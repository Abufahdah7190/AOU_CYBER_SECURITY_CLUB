# نادي الأمن السيبراني — Backend (المرحلة 4: قاعدة البيانات + نظام Auth)

هذا الدليل يشرح كيف تشغّل المشروع محليًا، وكيف تنشره مجانًا على Render (للسيرفر) وSupabase (لقاعدة البيانات).

## ما الذي تغيّر في المشروع

- **لم يُحذف أو يُعدَّل أي ملف من الموقع الحالي.** `index.html`, `css/`, `js/`, `locales/` كما هي تمامًا في جذر المشروع.
- أُضيف مجلد **`server/`** جديد بالكامل يحتوي الـ Backend، ويخدّم ملفات الموقع الحالية كما هي بالإضافة إلى الـ API الجديد، على نفس المنفذ (لا حاجة لخادمين منفصلين ولا مشاكل CORS بين الواجهة والـ API).
- تمت إضافة `server/db/migrations/001_init.sql` الذي يبني **16 جدولًا** في قاعدة البيانات تغطي كل ما ورد في متطلبات المشروع (المستخدمين، الدورات، الدروس، الاختبارات، الشهادات، المقالات، الإشعارات، سجلات التدقيق...). المراحل القادمة ستستخدم بقية الجداول تدريجيًا؛ هذه المرحلة **تُفعّل عمليًا** فقط: `users`, `refresh_tokens`, `password_reset_tokens`, `audit_logs`.

## ما تم تنفيذه في هذه المرحلة (Auth)

جميع النقاط التالية **مُختبرة فعليًا** وليست كودًا نظريًا فقط:

| الميزة | الحالة |
|---|---|
| تسجيل حساب جديد (الاسم، الهاتف، البريد، كلمة المرور، التخصص) | ✅ مُختبر |
| منع تكرار البريد الإلكتروني | ✅ مُختبر |
| تشفير كلمات المرور (bcrypt, cost 12) | ✅ مُختبر |
| سياسة كلمة مرور قوية (10+ أحرف، حرف كبير/صغير/رقم) | ✅ مُختبر |
| تسجيل الدخول برسائل خطأ عامة (بدون كشف وجود الحساب من عدمه) | ✅ مُختبر |
| قفل الحساب تلقائيًا بعد 5 محاولات فاشلة (15 دقيقة) | ✅ مُختبر |
| جلسات آمنة عبر httpOnly cookies + access/refresh tokens مع تدوير (rotation) | ✅ مُختبر |
| تسجيل الخروج (إبطال الجلسة فعليًا في قاعدة البيانات) | ✅ مُختبر |
| استرجاع كلمة المرور عبر رابط بريد إلكتروني صالح لمدة 30 دقيقة، استخدام واحد فقط | ✅ مُختبر |
| تعديل بيانات الحساب | ✅ مُختبر |
| تغيير كلمة المرور (مع إبطال كل الجلسات الأخرى) | ✅ مُختبر |
| Rate limiting على كل مسارات الـ Auth | ✅ مُختبر |
| نظام الأدوار (Student/Instructor/Reviewer/Admin/Super Admin) والـ middleware الخاص به | ✅ مُختبر (وحدويًا) |
| Audit Logs لكل حدث حساس (تسجيل، دخول، دخول فاشل، تغيير كلمة مرور...) | ✅ مُختبر |
| حماية SQL Injection (parameterized queries في كل مكان) | ✅ مُختبر |
| Helmet + CSP + rate limiting عام | ✅ مفعّل |
| إرسال إيميلات عبر Nodemailer + Gmail SMTP (مع تسجيل بالـ console بدل الإرسال إذا لم تُضبط بيانات الحساب) | ✅ مُختبر (بوضع dev) |

## التشغيل محليًا

### المتطلبات
- Node.js 18+ 
- PostgreSQL محلي، أو حساب Supabase مجاني (الأسهل)

### الخطوات

```bash
cd server
npm install
cp .env.example .env
```

افتح `.env` وعدّل:
- `DATABASE_URL` — رابط اتصال قاعدة بياناتك (محلي أو Supabase)
- `JWT_ACCESS_SECRET` و `JWT_REFRESH_SECRET` — ولّد قيمًا عشوائية قوية:
  ```bash
  node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
  ```

ثم:

```bash
npm run migrate   # ينشئ كل الجداول في قاعدة البيانات
npm run dev        # يشغّل السيرفر مع إعادة تحميل تلقائي (nodemon)
```

افتح `http://localhost:3000` — سترى الموقع الحالي كما هو تمامًا، مع الـ API الجديد متاح تحت `/api/*`.

اختبار سريع:
```bash
curl http://localhost:3000/api/health
```

## النشر المجاني (Render + Supabase)

### 1. قاعدة البيانات — Supabase (مجاني)
1. أنشئ حسابًا في [supabase.com](https://supabase.com) وأنشئ مشروعًا جديدًا.
2. من **Project Settings → Database → Connection string → URI**، انسخ رابط الاتصال (يشبه: `postgresql://postgres:[YOUR-PASSWORD]@db.xxxxx.supabase.co:5432/postgres`).
3. أضف `?sslmode=require` في نهاية الرابط.

### 2. السيرفر — Render (مجاني)
1. ارفع هذا المشروع كاملًا (بما فيه `server/`) إلى مستودع GitHub.
2. في [render.com](https://render.com): **New → Web Service** → اختر المستودع.
3. الإعدادات:
   - **Root Directory:** `server`
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
4. أضف متغيرات البيئة (Environment) من `.env.example`، بما فيها `DATABASE_URL` من Supabase، وقيم JWT العشوائية، و`NODE_ENV=production`، و`FRONTEND_URL` = رابط تطبيقك على Render نفسه (مثلًا `https://your-app.onrender.com`).
5. بعد أول نشر، شغّل الـ migration مرة واحدة من **Shell** الخاص بـ Render:
   ```bash
   npm run migrate
   ```

### 3. البريد الإلكتروني — Gmail SMTP عبر Nodemailer (مجاني)
1. فعّل **التحقق بخطوتين (2-Step Verification)** على حساب Gmail الذي سيرسل الإيميلات.
2. من **Google Account → Security → App passwords**، أنشئ App Password جديدة (16 حرفًا) — لا تستخدم كلمة مرور Gmail العادية، لن تعمل.
3. أضف `EMAIL_USER` (عنوان Gmail) و`EMAIL_PASS` (الـ App Password) في متغيرات البيئة على Render — بدون أي تعديل بالكود.
4. هذا يرسل لأي مزوّد بريد (Gmail, Outlook, Yahoo...) بدون أي تحقق نطاق إضافي، على عكس نطاق Resend المجاني الذي كان يرفض (403 Forbidden) الإرسال لغير حساب Resend نفسه.

## ملاحظة أمان مهمة لمرحلة الواجهة القادمة

عند بناء صفحات تسجيل الدخول/التسجيل/الملف الشخصي في `index.html` لاحقًا، يجب عرض أي بيانات قادمة من المستخدم (مثل الاسم) عبر `escapeHtml()` الموجودة أصلًا في `js/script.js` — تمامًا كما يفعل الموقع حاليًا مع نتائج فحص الروابط والملفات — لمنع XSS. الـ API الحالي يخزّن البيانات كما وردت (هذا سلوك صحيح لقواعد البيانات)، والحماية الفعلية من XSS تكون دائمًا عند العرض في المتصفح.
